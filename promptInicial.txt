Você será o arquiteto e desenvolvedor principal do **ProjetoPizza**, um sistema completo de gestão para pizzaria.

Trabalhe diretamente no repositório aberto no ambiente.

Os designs exportados pelo Google Stitch estão localizados em:

```text
C:\teste\designs
```

Esses arquivos devem ser analisados antes da implementação. Eles representam a referência visual e funcional do sistema.

## Objetivo desta primeira tarefa

Crie a fundação real do sistema utilizando:

* .NET 10;
* C#;
* ASP.NET Core;
* Entity Framework Core;
* PostgreSQL;
* Npgsql;
* DDD pragmático;
* Clean Architecture;
* Clean Code;
* princípios SOLID;
* testes automatizados;
* frontend administrativo responsivo.

Além da estrutura arquitetural, crie a primeira versão das entidades de domínio necessárias para atender às funcionalidades encontradas nos designs.

A prioridade visual desta etapa é a **interface administrativa**.

Não implemente ainda toda a interface do tablet do cliente, mas mantenha a arquitetura preparada para ela.

Não solicite confirmação para decisões técnicas que possam ser tomadas com segurança. Documente as decisões e prossiga.

Antes de criar ou alterar qualquer arquivo:

1. percorra todos os diretórios dentro de `C:\teste\designs`;
2. leia todos os arquivos HTML, CSS, JavaScript, imagens e arquivos auxiliares;
3. identifique todas as telas administrativas;
4. identifique telas duplicadas ou versões atualizadas;
5. dê preferência às telas marcadas como atualizadas, quando isso estiver claro;
6. identifique:

   * cores;

   * espaçamentos;
   * componentes;

## Convenções do banco

Utilize:

```text
UUID para identificadores técnicos
numeric(18,2) para valores monetários
timestamp with time zone para datas
snake_case para tabelas e colunas
```

No código C#:

```text
Guid ou IDs fortemente tipados
decimal para dinheiro
DateTimeOffset para datas
```

Armazene datas em UTC.

Não utilize `double` ou `float` para valores monetários.

Não utilize Data Annotations de persistência nas entidades do domínio.

Configure o EF Core usando classes que implementem:

```csharp
IEntityTypeConfiguration<TEntity>
```

Não coloque senha ou credencial no repositório.

Crie:

```text
appsettings.json
appsettings.Development.json
.env.example
compose.yaml
```

O `compose.yaml` deve subir apenas o PostgreSQL, com:

* volume persistente;
* health check;
* usuário e senha configuráveis;
* porta configurável;
* banco `projeto_pizza`.

# 5. Regras para o Domain

O projeto `ProjetoPizza.Domain` não pode depender de:

* Entity Framework Core;
* ASP.NET Core;
* banco de dados;
* JSON;
* controllers;
* bibliotecas de frontend;
* Infrastructure;
* Application.

As entidades devem:

* possuir construtores controlados;
* preservar suas invariantes;
* evitar setters públicos;
* disponibilizar métodos com intenção de negócio;
* possuir nomes em inglês;
* utilizar tipos fortes;
* impedir estados inválidos.

Não crie entidades puramente anêmicas quando houver comportamento claro.

Não crie abstrações somente para afirmar que está utilizando DDD ou SOLID.

# 8. Persistência e EF Core

Crie configurações individuais para todas as entidades implementadas.

Exemplo:

```text

  Persistence/
    ProjetoPizzaDbContext.cs
    Configurations/
      Core/
      Catalog/
      Dining/
      Ordering/
      Production/
      Billing/
      Cashier/
      Devices/
      Inventory/
```

Configure corretamente:

* nomes das tabelas;
* schemas;
* chaves;
* índices;
* foreign keys;
* conversões de IDs fortemente tipados;
* owned types ou conversões para `Money`;
* precisão decimal;
* tamanho máximo das strings;
* comportamento de exclusão;
* restrições únicas;
* concorrência otimista.

Crie índices para consultas frequentes, incluindo:

```text
restaurant_tables(unit_id, number)
table_sessions(unit_id, status)
orders(unit_id, status, placed_at)
order_items(order_id, status)
service_calls(unit_id, status, created_at)
kitchen_tickets(production_station_id, status)
payments(bill_id, status)
cash_shifts(cash_register_id, status)
devices(unit_id, status)
products(unit_id, category_id, is_active)
pizza_flavor_prices(pizza_flavor_id, pizza_size_id)
```

Não utilize cascade delete em registros transacionais importantes.

Pedidos, pagamentos, caixas e auditoria nunca devem ser apagados automaticamente.

Crie a migration inicial:

```text
InitialCreate
```

A migration deve corresponder somente às entidades realmente implementadas.
